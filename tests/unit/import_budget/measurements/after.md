# The after measurement: per-verb import cost

This is the post-change record for the per-verb import cost work (issue #455;
spec `docs/superpowers/specs/2026-09-26-per-verb-import-cost-design.md`,
§3.3). It sets the finished branch against the base it lands on.

- **After tree:** branch `per-verb-import` at `511c27c6` (main merged in),
  plus the commit that adds this file. That commit changes no counting: it
  promotes `tracked_run_local` to the gated `dispatch_local_warm`, lowers the
  target ratios and regenerates the ceilings.
- **Before tree (the merged base):** `main` at `e122e9b7`, the commit the
  branch merged. See "Why the before is re-measured" below.
- **Harness:** `scripts/import_budget.py` and its fixture
  `tests/_fixtures/generated_repo.py` from `511c27c6`, the same two files on
  both trees. Their counting code is the frozen code `before.md` used.
- **Date:** 2026-09-26.
- **Machine:** the aarch64 dev VM. CPython 3.10.20 from the uv dev env
  (`.venv`), and CPython 3.14.3 from the `tests_hostless-3.14` nox env.

Do not edit this file. Like `before.md`, its numbers change only under the
measurement-freeze rule.

## Why the before is re-measured

`before.md` measured `954c1568`, where the branch started. `main` moved
after that: dependency bumps and the UDP tunnel carrier. The after tree
carries those changes, so comparing it with `954c1568` would credit or charge
the branch for work it did not do. The before numbers here come from
`main`'s own tree at `e122e9b7`, measured by this branch's harness, so the
only difference between the two sides is the branch's product work.

`before.md` stays as it is, the historical record of the branch's start. On
3.10, `main`'s movement shifted the gated `file_ops` by between -18
(`help_repo`) and +2 (`help`) against `before.md`'s table B; the verb
`--help` surfaces moved by -2.

How the merged base was measured:
- A throwaway detached worktree of `e122e9b7`, with `uv sync`, and for 3.14
  `nox -s tests_hostless-3.14 --install-only`. `make web` was not run: no
  surface touches `otto._webassets`, as no ceilings file has an
  `otto:_webassets` bucket. The gcov submodule was not needed either.
- `scripts/import_budget.py` and `tests/_fixtures/generated_repo.py` were
  copied in from `511c27c6`. The fixture adds the `local_true` instruction
  that `tracked_run_local` dispatches, and the closed-port SSH lab the
  `host_ssh_*` surfaces need. Every surface ran on `main`'s tree and exited
  as expected, so no row is n/a.
- In the before tables the surface keeps the key it had there,
  `tracked_run_local`. Table C lists it under its new key.

## The headline

Summed over the 25 gated surfaces, `file_ops` fell from 81,297 to 57,046 on
CPython 3.10 (-29.8%) and from 83,648 to 59,268 on 3.14 (-29.1%). No gated
surface rose on either interpreter, and none rose on 3.11 to 3.13 against
the ceilings they replace.

- A verb's `--help` now costs about half of what it did: `host`, `docker`,
  `monitor`, `test` and `cov` fell by 48% to 51%, to about 1,200 file
  operations each, and `help`, `run`, `reservation` and `schema` by about 30%.
- A command that needs no SSH no longer pays for asyncssh and its liboqs
  probe: `dispatch_repo_warm`, `dispatch_local_warm` and `host_local_exec`,
  `put` and `get` fell by about 45%. Before, each started `ld`, `gcc`,
  `collect2`, `ldconfig`, `git`, `bash` and `stty`. Now `dispatch_repo_warm`,
  `host_local_put` and `host_local_get` start no child process at all,
  `host_local_exec` starts only the `sh` that runs its command, and
  `dispatch_local_warm` only the `bash` and `stty` of its `LocalHost`
  session.
- `test_repo` fell by 28% and starts no child process. The SSH surfaces,
  which must load asyncssh, fell by 7.6%; they still run the liboqs probe
  (`ld`, `gcc`, `collect2`, `ldconfig`) but no longer `git`, `bash` or
  `stty`.
- `version_repo`, `import_otto` and `completion_repo_warm` were already
  minimal and did not move.

### The two bootstrap surfaces measure what `otto` pays

`run_bootstrapped` and `bootstrap_repo` import `otto` in a harness child
rather than through `otto._shim`, so until the final review their child did
not set `PYDANTIC_DISABLE_PLUGINS` the way the shim does, and the first
settings model paid pydantic's plugin scan: one file operation per installed
distribution, a cost no `otto` run pays. The child now mirrors the shim's
`setdefault`, and both surfaces' after numbers above drop by 130-131 on
every minor (3.10: `bootstrap_repo` 2295 → 2164, `run_bootstrapped`
2200 → 2069). Their before numbers still include the scan, since the base
harness measured it too, so about 131 of each surface's change is that
correction rather than product work. The old-metric Table A rows for these
two surfaces were not re-measured and still include it. Neither surface has
a target ratio; no target moved.
