# The before measurement: per-verb import cost

This is the pre-change record for the per-verb import cost work (issue #455;
spec `docs/superpowers/specs/2026-09-26-per-verb-import-cost-design.md`,
§3.3). It was measured on the unchanged product tree, so it is what the
after numbers are compared with.

- **Base commit (`<BASE>`):** `954c1568`. The product tree measured is
  this commit's `src/otto`.
- **Harness:** `scripts/import_budget.py` as committed in "test(budget):
  harden the ceilings harness's cache and baselines", the commit after
  `b07cbf03`, which is the measurement-freeze point. The tables were taken
  with `6849b2e5`. The later commit adds only checks and a pinned compile
  mode, and it measured every gated row identical on 3.10 and 3.14.
- **Date:** 2026-09-26.
- **Machine:** the aarch64 dev VM. CPython 3.10.20 from the uv dev env
  (`.venv`), and CPython 3.14.3 from the `tests_hostless-3.14` nox env.

Do not edit this file. Its numbers change only under the measurement-freeze
rule, which re-measures the base tree with the same harness.

## How it was measured

**Table A (old metrics)** comes from the pre-change harness,
`git show 954c1568:scripts/import_budget.py`, run with no flags.
- The script finds its fixtures through `REPO_ROOT = Path(__file__).parent.parent`,
  so a copy outside the checkout is loaded by path, and `REPO_ROOT` is pointed
  at the checkout before `main()` runs. The counting code is unchanged. The
  wrapper is:

  ```python
  import importlib.util, sys
  from pathlib import Path

  script, root = sys.argv[1], Path(sys.argv[2]).resolve()
  spec = importlib.util.spec_from_file_location("old_import_budget", script)
  mod = importlib.util.module_from_spec(spec)
  spec.loader.exec_module(mod)
  mod.REPO_ROOT = root
  sys.argv = ["import_budget.py"]
  raise SystemExit(mod.main())
  ```

- The old harness reads whatever bytecode the interpreter has cached in
  place, and its `open` and `stat_tot` columns follow that state: with the
  venv's `.pyc` files deleted, `help` read `open` 581 and `stat_tot` 1418,
  against 245 and 1194 warm. So before the runs, every directory on the
  interpreter's `sys.path` was compiled in place, with no
  `PYTHONPYCACHEPREFIX` set:

  ```bash
  python -m compileall -q $(python -c "import sys, os; print(' '.join(p for p in sys.path if p and os.path.isdir(p)))")
  ```

  Two runs followed, and they were identical; the second is recorded. The
  other columns do not depend on the bytecode cache.
- The after numbers must be measured the same way: the same file, the same
  compile first, two runs, the second one recorded.

**Table B (new metrics)** comes from `--report-json` with the frozen
harness. It lists every surface in the table, gated and tracked. Every child
reads a warm bytecode cache the harness owns, so the numbers do not depend
on the machine's own `.pyc` files. The gated rows match the committed
ceilings files (`tests/unit/import_budget/ceilings/3.10.json` and `3.14.json`)
exactly, on both interpreters: a difference of 0 on every gated row.

Column meanings:
- **Table A:** `total` is every module in `sys.modules`. `non_std` is the
  modules outside the stdlib, less what a bare interpreter already carries.
  `otto` is otto's own modules. `stat_ws` and `stat_tot` are strace's
  stat-family counts for the interpreter's own threads: under the workspace
  (repo lib-dir probes excluded), and in total. `open`, `scandir` and
  `listdir` come from the audit hook; `listdir` counts directories, not calls.
- **Table B:** `file_ops` is every path syscall across the whole process
  tree. `workspace` is the subset under the generated repo and `OTTO_HOME`.
  The top buckets say where the operations went: `site:<package>`,
  `otto:<subpackage>`, `stdlib`, `workspace`, `fd` (calls on an open
  directory) and `other` (interpreter start-up, the child processes' own
  files, the harness's empty cwd). The child processes are the programs the
  command started, with their operation counts. `python` is left out.
