# BusyBox Bed Guests + Artifact-Tier Migration — Design

**Date:** 2026-08-20
**Status:** Approved design, pre-implementation
**Sequencing:** ships BEFORE
`docs/superpowers/specs/2026-08-20-host-probe-protocol-survey-design.md`,
whose live e2e lands on the bed this spec builds.

## 1. Problem

otto's BusyBox coverage today is the artifact tier: real pinned binaries from
busybox.net driven through deliberately contrived local setups — a
restricted-PATH/rootfs harness standing in for a host, qemu-user-static on
non-x86, and fake host plumbing carrying the applets. The binaries are real;
everything around them is not. Remote-shell semantics, telnet login, command
framing over a live session, and transfer paths are exactly the parts a
harness cannot exercise, and they are the parts BusyBox devices actually
stress.

Meanwhile the bed has no BusyBox host at all, so nothing BusyBox-shaped is
ever validated in a real lab setup.

**Goal (Chris, verbatim intent):** stand up real BusyBox QEMU guests in the
lab, one per milestone version, and deprecate the contrived-setup tests by
moving them all to real qemu remote hosts.

## 2. Decisions locked during brainstorm

- **Five guests, one per pinned milestone version** — the exact set the
  artifact tier pins today: 1.16.1 (i686), 1.21.1 (i686), 1.28.1 (x86_64),
  1.31.0 (x86_64), 1.35.0 (x86_64).
- **Hosted on test1** (10.10.200.11, lab element `carrot`), NOT the zephyr
  VM: a wedged BusyBox experiment must not take down embedded coverage.
  test1 becomes the bed's second hop.
- **Behind the VM as hop:** QEMU user-mode networking; each guest reachable
  only from inside its host VM (telnet to a per-guest loopback port). The
  guests are unix-family hosts with `hop = <vm-host-id>` — the mechanism
  `unix_host.py` already implements (`_build_hop_transport`), the same shape
  as sprout-behind-basil.
- **Codified in the `Vagrantfile`** — the test-VM definition (the
  `config.vm.define` loop) gains the BusyBox provisioning for the designated
  VM; `vagrant provision` reproduces the capability from scratch, no
  hand-configured state.
- **Recovery is a Makefile target:** `scripts/lab_health.py` learns the
  `busybox-qemu-*` units so `make qemu-restart` (or a sibling target if the
  plan finds the split cleaner) restarts and health-checks the whole bed —
  embedded and BusyBox — in one command. `make vm-health` reports them.
- **The artifact-tier tests migrate to the guests; the contrived harness is
  deprecated.** The pin/fetch layer of `tests/_fixtures/busybox.py`
  survives with a new job — it feeds guest image builds.

## 3. Guest design

- Minimal image per version: a small kernel plus an initramfs whose userland
  IS the pinned BusyBox artifact — built (or fetched-and-assembled) by a
  script the repo carries, consuming the same `busybox_pins.json` +
  fetch/verify layer the artifact tier uses today. The pin's two-layer trust
  story (hash first, behavioural banner second) carries over unchanged to
  image builds.
- Each guest runs `telnetd` (BusyBox's own) as its term entrypoint — BusyBox
  ships no sshd, so `term = telnet` is the honest and only login path. A
  fixed login/password baked at image build, recorded in lab data creds.
- QEMU user-mode net with one hostfwd per guest: `localhost:<port_N>` on the
  host VM → guest port 23. The i686 versions run under the x86 system
  emulator exactly as the artifact tier ran them under user-mode emulation —
  same bytes, now with a real kernel and network stack.
- One systemd unit per guest (`busybox-qemu-<version>.service`), journald as
  the no-restart diagnosis window — the same operational pattern the Zephyr
  units established, including the lesson that an abruptly severed session
  can wedge a guest and the unit restart is the recovery.

## 4. Lab data

Five new host entries under a `busybox` lab tag in the shared lab data:
unix-family (`os_type = "unix"`), `ip = "127.0.0.1"` with the per-guest
telnet port in `telnet_options`, `hop = "<vm-host-id>"`,
`valid_terms = ["telnet"]`, `valid_transfers = ["shell", "nc"]`, per-version
`userland_options` pins (RECON ONCE, THEN PIN — the pins may be generated by
running the recon against the provisioned guests once, then committed), and
per-guest resources. ssh is undeclared and dead by construction — which the
probe spec later uses as a permanent drift-table true-negative.

The hop is test1's existing lab host entry (element `carrot`, board seed),
which joins the `busybox` lab alongside its `veggies` membership — hop
resolution anchors on it exactly as `basil_seed` anchors the sprout entries.

## 5. Test migration and harness deprecation

- **Inventory:** every test selected by `-m busybox` (spread across
  `tests/unit/host/` — shell transfer, gap registry, privilege, power,
  history suppression, os_profile, run-line-length, nc listener reap,
  artifact checks) plus the `busybox_rootfs.py` harness consumers. The plan
  enumerates the precise list; the migration is 1:1 in intent — each test's
  discriminating assertion is preserved against a real guest,
  parametrized over the five versions where the original swept versions.
- **Anything unmigratable is flagged, never silently dropped.** A test whose
  premise cannot be expressed against a remote host (e.g. it manipulated the
  harness itself) is listed with a disposition — migrate differently, keep a
  unit-level remnant, or retire with a stated reason. "Not attempted" beats
  "silently half-moved".
- **Deprecated and deleted:** `busybox_rootfs.py`, the restricted-PATH
  host-double machinery, and the qemu-user-static execution path for tests.
  **Retained:** `busybox.py`'s fetch/pin/verify layer (now the image-build
  input) and `busybox_pins.json`.
- **Lane placement:** the migrated tests are bed tests. They join the
  bed-lane markers and run where bed tests run (`make coverage`'s unix lane,
  stability lanes as appropriate), excluded from hostless lanes like every
  other bed test.
- **The CI busybox lane is RETAINED, with a narrowed, honest scope.** The
  lane keeps running in CI, executing the five pinned binaries directly:
  artifact pin integrity plus the behavioural banner gate — the guards on
  the exact bytes the guest images are built from — and any applet-level
  checks that need no fake-host plumbing. What leaves the lane is only the
  contrived part: the restricted-PATH/rootfs host-double tests, whose
  intent migrates to the bed guests. So CI still exercises real BusyBox
  bytes on every run; host-*behavior* coverage (remote shell, telnet,
  transfers) lives on the bed, like every other bed suite.
- `make busybox` / `make busybox-cache` stay, backing the retained CI lane
  and doubling as the image-build input workflow;
  `docs/guide/hosts/busybox.md` is updated to describe the guests, the
  recovery target, and the split (CI = artifact tier, bed = behavior).

## 6. Health, recovery, and operations

- `scripts/lab_health.py` gains the BusyBox units (status + restart), on the
  designated VM, alongside the Zephyr ones; `make qemu-restart` recovers the
  whole bed in one command; `make vm-health` reports both beds.
- The journald window is the diagnosis path (documented next to the Zephyr
  wedge post-mortem pattern): inspect before restarting when a guest wedges.
- Provisioning is idempotent: re-running `vagrant provision` on the
  designated VM converges (fetch skipped on warm cache, units reinstalled,
  guests restarted only when their image changed).

## 7. Verification of the capability itself

- **Provisioning:** a provision run on the designated VM leaves five units
  active and health-checked; asserted by `lab_health` extensions.
- **Per-guest smoke (bed test):** telnet login from the hop succeeds on each
  guest; `busybox --help` banner matches the version the unit claims —
  the artifact tier's behavioural banner gate, now live.
- **Recovery:** the restart target brings a deliberately stopped unit back
  and the health check goes green (exercised once on the live bed at
  provisioning time; codified as the same runbook the Zephyr bed uses).
- **Migrated tests** are their own verification: green against real guests,
  with the per-version parametrization proving the version spread survived
  the migration.
- House rule stands throughout: **applying any of this to the live VMs is
  Chris's step** — provisioning artifacts land in the repo; nothing powers
  or reconfigures a real lab VM without explicit authorization.

## 8. Out of scope / deferred

- The probe protocol survey itself (its own spec, sequenced after this).
- ssh/dropbear on the guests — telnet is the honest single term.
- Non-x86 guest architectures.
- CI reaching the lab bed (bed coverage is local by design).
- Auto-generating lab-data pins on every provision (pins are committed,
  regenerated deliberately).
