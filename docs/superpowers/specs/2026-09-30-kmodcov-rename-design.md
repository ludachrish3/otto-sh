# otto_kgcov becomes otto_kmodcov — one name for kernel-module coverage in any format

**Date:** 2026-09-30. **Status:** approved in conversation, awaiting review of this text.
**Follows:** `2026-09-28-kgcov-kernel-compatibility-ladder-design.md` (landed as origin/main ec9ed790, PR #540).
**Precedes:** the control-surface spec (dump and reset without debugfs) and spec 2 of `todo/clang-kernel-coverage.md` (the clang source-based backend).

## 1. Problem

The library is named after one format. It already serves two producers of that format (gcc's gcov and clang's gcov-compatible mode), and the next two specs add clang's own raw profiles behind the same module, the same control files and the same output directory. `otto_kgcov` then understates what the library does, and every new file, macro and docs page written under that name would be renamed again later. The todo proposed `otto_kcov`; that name collides with the kernel's own KCOV subsystem (`CONFIG_KCOV`, `/sys/kernel/debug/kcov`), which users of a coverage tool know. Chris chose `otto_kmodcov` on 2026-09-30: coverage of kernel modules, any format, no collision.

## 2. Goals and non-goals

### Goals

- One name everywhere, in one cutover: `otto_kmodcov`, stem `kmodcov`, macro prefix `KMODCOV_`, class prefix `Kmodcov`. After the change, `git grep -i kgcov` finds the old name only in frozen history (§3).
- The behaviour of the module and of otto is identical before and after, with one exception stated in §4.3, so the existing tests, the export identity test and the compatibility matrix prove the rename.
- The change is scripted and reviewable as a rename: moves first, one case-preserving substitution second, hand edits third, each in its own commit.

### Non-goals

- No aliases, shims, deprecation warnings or dual names. The repository carries no backward-compatibility obligation at this time; a settings file that still declares `kind = "kgcov"` is refused with the ordinary unknown-kind error.
- No change to the control surface (debugfs stays; the debugfs-free path is the next spec), no new backend, no change to the ladder, the linker script or the matrix rows.
- No rewriting of frozen history: earlier spec files keep their names and text, `CHANGELOG.md` is generated from commit subjects and is never edited, GitHub issues keep their titles.
- No change to gcov-format names: `.gcda`, `.gcno`, `gcov_info`, `__gcov_init`, `llvm_gcov_init`, the vendored `GCOV_` constants, `kernel/gcov` references and the `gcov`/`llvm-cov gcov` tool kinds all stay. They contain `gcov`, never `kgcov`, which is what makes the substitution in §4.2 safe.

## 3. Decisions and rules

1. **Stem and spellings.** `kgcov` → `kmodcov`, `Kgcov` → `Kmodcov`, `KGCOV` → `KMODCOV`, in identifiers, paths, strings, prose and rendered titles alike. `otto_kgcov` therefore becomes `otto_kmodcov`, `otto.kgcov` becomes `otto.kmodcov`, `--kgcov` becomes `--kmodcov`, `make kgcov` becomes `make kmodcov`.
2. **Frozen history is the only exception**: the four earlier spec files under `docs/superpowers/specs/` whose names carry `kgcov`, and `CHANGELOG.md`. Everything else tracked in the repository is in scope, including the vendored copy under `tests/repo5/third_party/`, which is regenerated by the export, never hand-edited.
3. **The interface number stays 1.** `KMODCOV_INTERFACE` and `otto.kmodcov.library.INTERFACE` both read 1; nothing older exists to be told apart from. The modinfo version suffix becomes `+kmodcov<n>` and the parser that reads it moves with it.
4. **One semantic change rides along**: the module parameter `gcov_dir` becomes `cov_dir` (§4.3). It is renamed here, not in spec 2, because otto passes it at one call site and every docs page that names it is being touched anyway.
5. **Provisioning caches are renamed too** (§4.4): image tag, image label, kernels directory and its environment override. A cache name that kept the old stem would be the one place the grep in goal 1 finds it.
6. **The matrix is re-measured under the new names**, not carried over: every measured cell names a test nodeid that exists, and `as_of` says when that test ran.
7. **Rendered meaning is unchanged by the reflow.** The new stem is two characters longer; lines that cross a limit (C at 100 columns, Python under ruff, markdown tables, shell) are reflowed with no change to what they say or render.

### 4.2 The mechanism

1. **Moves first.** `git mv` for every tracked path outside frozen history whose name carries the stem, directories included, so history follows the files.
2. **One substitution second.** Over every tracked text file outside frozen history, in this order: `kgcov` → `kmodcov`, `Kgcov` → `Kmodcov`, `KGCOV` → `KMODCOV`. No word boundaries are needed: the stem `kgcov` is a substring of no identifier that must survive, because every gcov-format name (`gcov_info`, `__gcov_init`, `llvm_gcov_init`, `GCOV_TAG_FUNCTION`, `.gcda`, `kernel/gcov`) lacks the leading `k`. The plan proves this the cheap way: it prints the distinct set of identifiers the substitution touched and the reviewer reads it once.
3. **The generated files follow their generators.** `kmodcov_version.h` is written by the export (`VERSION_HEADER` in `library.py`), the vendored copy under `tests/repo5/third_party/otto_kmodcov/` is written by `export_tree`, and `docs/cli/cov/instrumenting/kmodcov-matrix.md` is written by the renderer at docs build; each is regenerated, and the export identity test proves the copy.
4. **Hand edits third**: the reflow of rule 7, prose where the old name was used as a word rather than an identifier, and the matrix page title. Nothing else is written by hand.

### 4.3 The one semantic change: `gcov_dir` becomes `cov_dir`

The library's `KMODCOV_DECLARE` declares the parameter and its description; `KMODCOV_INIT()` passes it to `kmodcov_register`; otto's kmod product kind appends `cov_dir=<cov_dir>` to `insmod` and refuses a `params` string that sets it itself; the dev-tool kind refuses the same; the docs name it on the kernel-modules, declared-products and getting-started coverage pages. Word-bounded `gcov_dir` → `cov_dir` after the stem substitution touches exactly those sites (`kgcov_dir`, the vendoring directory option, has already become `kmodcov_dir` and is not matched). The parameter's meaning is unchanged: the absolute directory the module's coverage files are written under. Its description says "coverage files", no longer ".gcda files", because spec 2 writes raw profiles there too.

### 4.4 The provisioning caches on the dev VM

The image tag prefix, the recipe label and the kernels directory are renamed in the script and the Makefile defaults. Migration is one plan task, on this VM only: move the directory (`mv /home/vagrant/build/kgcov-kernels /home/vagrant/build/kmodcov-kernels`, 1.4 GB, no copy; the trees' stamps name the recipe hash, which is unchanged, so no tree is redone); run the renamed provisioning script, which finds no image under the new tag and builds each one — the Dockerfile text and the pinned context are unchanged and the label is passed on the build command line, so every layer is served from cache in seconds and the six new tags share their layers with the six old ones; then remove the six old tags with `docker rmi otto-kgcov-kernel:<id>`, which drops the tags and frees nothing, since the layers now belong to the new tags. Disk cost of the migration is a few megabytes. This is the one deletion the plan performs, and it removes only tags this repository created.

### 4.5 Proof

- **The grep is empty**: `git grep -i kgcov -- . ':!docs/superpowers/specs' ':!CHANGELOG.md'` prints nothing, and `git grep -wE 'gcov_dir' -- . ':!docs/superpowers/specs' ':!CHANGELOG.md'` prints nothing.
- **The existing suites are the behaviour proof**: the unit suite including the export identity test (`tests/unit/test_kmodcov_export.py`), `make docs` (the renderer writes `kmodcov-matrix.md`, the API page resolves `otto.kmodcov`), `make typecheck`, `make lint-arch`, the repo5 demo build (`tests/repo5/kmod/build.sh`), then the full `make kmodcov` run — bed columns and the 63 build cells — followed by `make kmodcov-matrix`, whose fold is committed as the re-measured artifact (rule 6), `nox -s tests_hostless-3.14`, `make coverage`, `make gate-fresh`.
- **The scaffold proof**: `otto init --kmodcov` in a scratch repository vendors `third_party/otto_kmodcov/`, writes `kind = "kmodcov"`, and `otto cov kmodcov check` on the result reports current.

## 5. Files

Every path in §4.1 moves; every file among the 104 changes. New files: none. Deleted files: none (moves only). The matrix artifact changes content as well as name (re-measured).

## 6. Compatibility

None kept, by rule. A consumer tree vendored before this change keeps building against its own vendored copy until it re-runs `otto init --kmodcov` or `otto cov kmodcov export`; `otto cov kmodcov check` on an old copy reports every file absent, which is the intended signal. The bed hosts carry no state under the old name: the module is rebuilt and loaded per run and the coverage directory is created per product.
